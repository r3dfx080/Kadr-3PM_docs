# Кадр-3ПМ documentation knowledge base

Soviet 2" quadruplex VTR «Кадр-3ПМ» (М181). Documents are in Russian; OCR'd from scans, **not proofread yet**.

| Book | Folder | Sheets |
|---|---|---|
| М181-600-000 ИЭ — Инструкция по эксплуатации | `M181-600-000_IE/` | 121 (л.46, 98 absent — see book.json) |
| М181-600-000 ТО — Техническое описание | `M181-600-000_TO/` | 25 + 1 foreign insert |
| М181-700-000 Э4.1 — Схема электрическая соединений | `M181-700-000_E4.1/` | 20; wiring not transcribed |

How to navigate:
- Each book: `manifest.csv` maps sheet label → scan file; `pages/lNNN<suffix>.md` holds one sheet
  (`l032b.md` = лист 32б). Start from the book's table of contents page (`l002.md`).
- Search: `rg -i "<term>" kb/*/pages`. Designators are normalized: digit 1 (not I), Cyrillic letters (А104, Х3).
- Cite as `<doc> л.<sheet> п.<item>`, e.g. `М181-600-000 ИЭ л.40 п.6.11.3`.
- Handwritten corrections are applied in the text; the original wording is in an HTML comment and in `marks:`.
- If wording, a number, a figure or any wiring matters, look at the sheet image before answering:
  `SOURCES_JPEG/<book folder>/<page stem>.jpg` (grayscale, 2000 px — open this, not the 15 MB TIFF;
  e.g. `SOURCES_JPEG/M181-600-000_IE/l040.jpg`). The TIFF master is the page's `scan:` path.
- Abbreviations: `glossary.csv` lists abbreviations from the related **Кадр-103СЦ**, not this machine.
  Use it only as a hint: say "per the 103СЦ glossary, probably …" and never present it as the 3ПМ meaning
  unless `scope` includes `3ПМ`. Never edit page text based on it — propose a `suggestion` issue instead.
- `uncertain:` in a page's front-matter lists readings the OCR models doubted — check those against the image.
- OCR ingest: `python -I -X utf8 kb/tools/ingest.py <book> --batch 15` (Haiku, then Opus for sheets with risk
  score ≥ 6, then promote to `pages/`). Progress and where to resume: `INGEST_STATUS.md` (generated; run
  `ingest.py --status` to refresh). Batches are resumable; a usage-limit failure is retried on the next run.
- Viewer for people: double-click `viewer.bat` in the project folder (or run
  `python -I -X utf8 kb/tools/serve.py`) and use `http://127.0.0.1:8765/kb/viewer/index.html`: scan beside text,
  «Править текст» edits the page body, ticking an issue resolves it, «Вычитан» marks the sheet proofread; the
  index has a status filter («на вычитку» = proofreading queue) and statistics. Pages opened from disk show the
  same content but cannot save. Rebuilt by every `ingest.py`/`review.py` run and every save in the viewer, or
  by `python -I -X utf8 kb/tools/viewer.py`; `kb/viewer/` is not in git.
- Review database: `review.sqlite` (+ `review/*.csv` copies for diffs) holds page status and per-sheet issues
  (doubts, [неразборчиво], handwritten marks, OCR failures). Fix text in the viewer or the page file, then
  resolve issues and mark the sheet proofread in the viewer, or with `python -I -X utf8 kb/tools/review.py resolve <id>`
  and `… review.py proof <book> <stem>`; `review.py issues` lists open ones. A proofread or hand-edited page
  (including one saved from the viewer) is never overwritten by OCR.
- Abbreviation index: `abbreviations.csv` (generated by `review.py sync`, do not edit) lists every all-caps
  token with the sheets it is on; `likely_word=yes` = probably an ordinary word in capitals (panel label).
  Its `glossary` column is a 103СЦ hint unless the scope says 3ПМ — record confirmed meanings in `glossary.csv`.
- Rules and known gaps: `SCHEME.md`.
- Auditing pages against the spec: use the `kb-rescan` skill (`.claude/skills/kb-rescan/SKILL.md`) —
  report only, never edits.

Git (repository = the project folder that contains `kb/` and `SOURCES/`):
- Commit as the user's configured git identity only. **Do not sign commits as Claude or any AI**: no
  `Co-Authored-By: Claude …` trailer, no "Generated with …" lines, in commit messages or PR descriptions.
- `SOURCES/` and `SOURCES_JPEG/` are git-ignored; never force-add them.
